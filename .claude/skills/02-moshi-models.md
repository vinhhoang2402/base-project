# 02 - Moshi Models (Avoid Collisions!)

## THE PROBLEM: Model Naming Collisions

**BAD - Creates bugs:**
```
src/model/Response.kt       ← What feature?
src/model/Response.kt       ← COLLISION!
src/model/User.kt           ← Collides with 3 other "User" files
```

**GOOD - Clear + safe:**
```
feature/home/data/model/MovieResponse.kt
feature/auth/data/model/AuthResponse.kt
feature/auth/data/model/UserProfileEntity.kt
```

---

## File Naming Rules (MUST FOLLOW)

```
❌ BAD (Generic):
  Response.kt, Entity.kt, Model.kt, Data.kt, DTO.kt

✅ GOOD (Specific):
  MovieResponse.kt    ← Clear what it is
  UserAuthResponse.kt ← Clear what feature + purpose
  MovieEntity.kt      ← Domain model
  UserEntity.kt
```

**Rule:** Always prefix with domain/feature name!

## Template (Copy-Paste)

```kotlin
// feature/{name}/data/model/{Domain}Response.kt
package com.demo.projectbase.feature.home.data.model

import com.squareup.moshi.Json
import com.squareup.moshi.JsonClass

// API Model (generated by Moshi)
@JsonClass(generateAdapter = true)
data class MovieResponse(
    @Json(name = "id") val id: Int,
    @Json(name = "title") val title: String,
    @Json(name = "poster_path") val posterPath: String,  // ← snake_case in API
    @Json(name = "vote_average") val voteAverage: Double
)

// Domain Model (internal)
data class Movie(
    val id: Int,
    val title: String,
    val posterUrl: String,  // ← transformed URL
    val voteAverage: Double
)

// Mapper (convert API → Domain)
fun MovieResponse.toDomain() = Movie(
    id = id,
    title = title,
    posterUrl = "https://image.tmdb.org/t/p/w500$posterPath",
    voteAverage = voteAverage
)
```

## Quick Checklist

- [ ] File named: `{Domain}Response.kt` (not "Response.kt")
- [ ] In feature-specific package
- [ ] Has @JsonClass(generateAdapter = true)
- [ ] @Json(name = "...") for all snake_case fields
- [ ] Separate domain model
- [ ] Has toDomain() mapper
- [ ] NO generic names (Response, Entity, User)
